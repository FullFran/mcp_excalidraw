- L5 (2026-11-02, T1): `/mcp` uses the SDK's own `createMcpHandler` (`@modelcontextprotocol/server` 2.0.0; no `@modelcontextprotocol/node`/`express` adapter installed, so `src/core/mcp-http.ts` bridges Express to the web-standard Request/Response). 2025-era clients are served by the SDK's stateless legacy fallback: `initialize` works but no `Mcp-Session-Id` is issued and GET/DELETE answer 405. In-process tools are repointed at the server's own listener (`useInProcessCanvasUrl`) so HTTP tool calls hit the same canvas as REST. Host/Origin guard (SDK helpers) only on loopback binds, allowing the `PUBLIC_BASE_URL` hostname; `TRUST_PROXY` off by default. Auth seam for T2: `createMcpHttpRouter({ authMiddleware })`, principal via `res.locals.mcpAuthInfo`. Differential vs a7a6894: `--help`, stdio wire test, and REST responses identical; `/mcp` 404 -> 405 on GET.
- L6 (2026-11-02, T2): auth lives in `src/auth/` (no new dependency; `node:crypto`). Off on a loopback bind unless `AUTH_MODE=oauth`; required on any other bind (startup names each missing variable); `AUTH_MODE=off` off-loopback needs `ALLOW_INSECURE_NO_AUTH=true`. Stray auth vars on loopback without `AUTH_MODE` are ignored (assumption: avoids locking out local use). Built-in AS: RFC 8414/9728 metadata, code + PKCE S256 only, RFC 9207 `iss` on every authorization response, RFC 8707 `resource` checked, 60 s single-use codes (replay revokes), 1 h access / 30 d rotating refresh tokens with family revocation, CIMD (SSRF-safe pinned https fetch, cache) + DCR (public or client_secret_*). Loopback redirects match port-agnostically (RFC 8252 §7.3; assumption beyond strict exact match). Tokens opaque, stored as SHA-256 in `$EXCALIDRAW_DATA_DIR/auth-store.json` (0600), so `EXCALIDRAW_DATA_DIR` is required when auth is on; codes in memory. GitHub login with signed `state` cookie and `ALLOWED_GITHUB_LOGINS` re-checked on every request; signed stateless session cookie (`__Host-` + Secure on https, HttpOnly, SameSite=Lax, 7 d). `PUBLIC_BASE_URL` must be https (http only for loopback hosts) and origin-only when auth is on. Canvas/static need the cookie; `/api/*` cookie or bearer, cookie writes need same Origin/Referer; WS needs bearer or cookie + same Origin; `/health` reduced to status+service (so `excalidraw-canvas stop` cannot read the pid of an authenticated server). In-process MCP tools reach the gated REST API with a per-process random header (`withCanvasHeaders`). Consequence for T4: `Dockerfile.canvas` sets `HOST=0.0.0.0`, so the canvas image refuses to start until auth is configured (or explicitly made insecure). `check-local-bind`'s `HOST=::` case now fails on auth config before reaching the duplicate-listener guard (still exits non-zero). Docs: `docs/auth.md`.
